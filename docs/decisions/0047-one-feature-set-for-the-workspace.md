# ADR 0047 — One feature set for the workspace

- **Status:** Accepted (2026-10-09). Built
- **Related:** [ADR 0042](0042-the-reading-renderer-is-disconnected-and-memory-safe.md)
  (whose "graph" this defines as what the renderer's code can call),
  [ARCHITECTURE.md](../ARCHITECTURE.md) (whose crate boundaries the same
  definition governs)
- **Decision:** **Every member depends on `postio-workspace-hack`, a crate
  with no code that names each third-party crate the workspace builds with
  the union of the features its members ask for, generated by
  `cargo hakari`. A crate boundary is about what a crate's code can call,
  and the workspace-hack gives it nothing to call: the boundary checks do
  not walk into it, and still count the features it switches on.**

---

## Context

Cargo resolves a dependency's features from the packages a command
selects. `cargo check --workspace` builds `tokio` with every feature any
member asks for; `cargo test -p postio-storage --lib` builds it with the
features `postio-storage` alone asks for, which is a different artifact,
and so is everything above it. The first time a tree builds a crate on its
own it rebuilds a slice of the dependency graph the workspace build already
compiled.

That first time is every time here. Each issue gets a fresh worktree, and
`scripts/test-fast.sh` -- the inner loop CLAUDE.md asks for -- runs
`cargo test -p <crate> --lib` once per changed crate. Measured on a Mac
(2026-10-09, other sessions building, so the times are loose and the counts
are not), after one workspace build, the single-crate commands for eight
crates rebuilt:

| | Third-party crates rebuilt | Time |
|---|---|---|
| `cargo check -p`, before | 362 | 253 s |
| `cargo check -p`, with the workspace-hack | 0 | 42 s |
| `cargo test -p --lib`, before | 311 | 601 s |
| `cargo test -p --lib`, with the workspace-hack | 0 | 106 s |

`postio-storage`'s unit-test build went from 98 s to 1 s. Each rebuilt
variant also stays on disk beside the one it duplicates.

## Decision

1. **The crate.** `crates/postio-workspace-hack`, generated by
   `cargo hakari` from `.config/hakari.toml` for Linux on both arches and
   the Mac, and depended on by every member through
   `postio-workspace-hack.workspace = true`. After any change to a
   manifest's dependencies: `cargo hakari generate && cargo hakari
   manage-deps --yes`.
2. **A boundary is what a crate can call.** The workspace-hack has no code
   and re-exports nothing, so `postio-model` depending on it, and it on
   `tokio`, gives `postio-model` no way to name `tokio`. The boundary rules
   in `ARCHITECTURE.md` and ADR 0042 mean the crates reachable through
   real dependencies, with features as they are actually built. A banned
   crate the workspace-hack names is still a violation the moment a real
   dependency reaches it; a feature the workspace-hack switches on in a
   crate a guarded crate does call is still that crate's feature.
3. **What stays out.** Three exclusions, each because unifying it would
   change what a crate can call or what a package needs, not merely what
   gets compiled:
   - `postio-ffi` is not traversed. Its `uniffi` takes the `cli` feature,
     which is why `default-members` leaves it out (#1306); unified, every
     crate would build `uniffi_bindgen` and `clap`.
   - `glib-sys`, `gobject-sys` and `gio-sys`. GLib reaches the workspace
     through GTK and a dev-dependency; unified, every Linux build would link
     it, including the terminal's Flatpak, whose runtime is chosen without
     it.
   - `image`. The renderer decodes hostile images with exactly the four
     decoders it asks for (ADR 0042 rule 1); unified, it would carry every
     decoder any crate on the platform asks for.

## Costs, accepted

- **A pure crate compiles more on a cold tree.** `postio-model` cannot
  start until the workspace-hack's dependencies are built, so it no longer
  compiles early beside them, and building it alone in an empty tree
  builds the workspace's dependencies first. A cold workspace build
  measured 166 s before and 197 s after, on a busy machine; seeding
  (`scripts/worktree-seed.sh`) is what keeps cold trees rare.
- **Test-only features reach shipped builds.** A dev-dependency's feature
  is unified with the rest: `tokio`'s `test-util` is in every build.
  Checked rather than assumed, in the tokio this workspace locks (1.53):
  it reads an atomic before touching its pausable clock, so a build that never pauses time pays a
  load, not a lock. A test-only feature with a real cost is a reason to
  exclude that crate here.
- **One more step after a manifest change**, held by
  `scripts/checks/check-workspace-hack.py`.

## Enforcement

- `scripts/checks/check-workspace-hack.py` fails when `cargo hakari
  generate --diff` or `manage-deps --dry-run` would change anything; CI
  installs the pinned tool (`scripts/install-hakari.sh`).
- `scripts/checks/check-crate-boundaries.py` does not walk into the
  workspace-hack; its self-test holds both halves of rule 2.
- `scripts/checks/check-renderer-is-memory-safe.py` prunes it from the graph
  and keeps its features.
- `scripts/checks/check-unused-deps.py` leaves the workspace-hack's own
  dependencies to it; the root manifest excuses every member's line naming
  it.

## Rejected

- **Leave the pure crates out of the workspace-hack.** Tried and measured:
  to keep every boundary as a whole-graph rule, `postio-storage` and
  `postio-index` had to leave too, since `postio-demo` reaches the network
  crates through them. The single-crate checks then rebuilt 317 crates
  instead of 362, and `postio-storage` alone rebuilt more than before (145
  against 97), because the workspace build had moved further from it.
- **One target directory for every worktree.** It would share artifacts,
  and serialise every session on cargo's build lock, and each branch's
  crates would overwrite the last one's.

## Would change this

A crate whose unified features change what it does in a way a check cannot
see -- that crate is excluded here, as `image` is. Or cargo resolving
features per workspace rather than per command, which would make the crate
unnecessary.
