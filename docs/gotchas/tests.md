# Gotchas: tests and the headless compositor

- **The small demo's second inbox row is a digest, not a message.** `x` skips it in bulk selection and Return opens the digest. Storyboards pass it and assert the row they mean. A capture storyboard needs `preset = "vault"` for a capture sheet (#1807, #2080).
- **Waiting for a total also measures every other row.** Wait for the specific message, row or widget by identity; use a count only when the count is the property, settled against the store.
- **`unwrap_or_default()` on a test's own observation turns breakage into a false accusation.** It reads as "not ready yet" and times out. Unwrap in the observation path; `queued > 0` counts what this call added, not whether work exists.
- **A test fails only under load.** Record the sequence in the mock and assert order, not wall-clock overlap. Liveness deadlines go through `postio_test_support::scaled`/`patience`. "The server refuses X" is a persistent fault, not `inject_after`. `tokio::time::pause` misfires with real I/O. Prove a flake with `scripts/flake-check.sh -p <crate> --test <suite> <test>` before re-running. (enforced by: `check-test-deadlines-scale.py`, `check-no-clock-waits.py`)
- **A case that needs a sync pass still running parks it; it does not size a mailbox.** `MockBackend::hold(Held::Headers | Held::Bodies, mailbox, admit)` parks fetches until `release()`; wait for `parked()`. Backfilled bodies of a large mailbox cost 75 to 95 s on the engine thread (#2105, #2166); set `BackfillPolicy { background: false, .. }` when bodies are not the subject.
- **A global `tracing` subscriber at `DEBUG` captures Turso's per-statement traces.** That slows a loaded runner past a timing claim (#2167). Capture at the level the case reads.
- **A negative assertion passes when the mechanism never armed.** Add a positive control that waits on its condition, and a duration.
- **Locals drop in reverse, so a `TempDir` bound last goes first and a running engine recreates it.** Stop the engine in a `Drop` before the directory goes, as `BlobDir` does in `crates/postio-runtime/tests/runtime_suite/harness/mod.rs`.
- **Test binaries share `$TMPDIR`.** Names that restart at 1 per store (draft ids) collide: add the process id and a counter. `.cargo/config.toml` points `TMPDIR` at `target/tmp`; without that directory every `tempdir()` fails with NotFound.
- **A fixture must not do the application's job.** A test that goes red when a fixture loses a recount or an invented INBOX found a bug; keep the fixture honest (`crates/postio-storage/tests/storage_suite/seed_is_honest.rs`). (enforced by: `check-no-sentinel-mailbox-ids.py`, partly)
- **A tested `pub fn` or emitted event is not proof anything uses it.** For each event ask who repaints; for each `oneshot` `Job` ask who asks. Assert at the far end ("a store this app opened has had X done"). (enforced by: `check-uncalled-pub-fn.py`, for `pub fn` only)
- **`has_focus()` is false on a focused widget in a headless window.** Use `is_focus()`, `GtkWindowExt::focus`, or `state_flags().contains(gtk::StateFlags::FOCUSED)`.
- **A running Postio fails the desktop suite's activation cases.** It owns `dev.postio.Postio` on your session bus, so a second `activate` dies silently. Quit Postio and its Flatpak before `desktop::`.
- **`pump()` returns at once when nothing is pending.** To assert on pixels, count real frames and wait until two renders agree; stability is the precondition, never the assertion. Push a loud CSS override first to prove the harness sees change.
- **The test display lays nothing out for WebKit, which still renders the composer.** Assert on the cascade (`getComputedStyle(el).color`) or DOM attributes, never geometry (width counts). Reader layout is asserted headlessly in `postio-render`.
- **A `GtkWindow` joins the toplevel list at construction and the Rust handle's drop does not release it.** `destroy()` windows a test builds. Test a leak with a `WeakRef`: drop, turn the loop, require `upgrade()` is `None`.
- **A test removal needs a mutation verdict only as wide as its filters.** `scripts/test-removal-check.sh` judges the mutants its `--package`, `-f`, `--re` select; cargo-mutants runs only the mutated crate's tests unless `--test-package` names others. `profile.per-test-coverage` uses an experimental nextest wrapper; `scripts/test-coverage-sets.py` stops with "left no profile" if an upgrade breaks it.
- **A GTK case that acts before layout passes only while rendering is slow.** Wait for the fact the action depends on (`adjustment.upper()`, `is_mapped()`), not for the trigger.
- **One clean GUI-suite run on a loaded machine proves nothing.** Run each side of a bisect two or three times. Red on every commit for one person is machine state (state file, keyring), not the tree.
- **`settle()` runs GTK's loop inside one tokio poll, whose budget is 128 operations.** A case that opens and closes back to back without a real yield leaves `settle` spinning at 100% CPU. `settle` now uses `block_in_place` and panics after ten seconds; a new suite that turns the loop inside `block_on` needs the same.
